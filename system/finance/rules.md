# 거래·분류 공통 규칙

## 공통 의미와 개인 시트 표현

중복 집계 방지, 소득·소비·자금이동 구분, 근거 없는 확정 금지, 변경 후 검증은 공통 원칙입니다. 아래 상태명·양수 금액·열·분류 ID·환불 발생월 정책은 신규 추천 양식의 구현입니다. 기존 시트에서는 확인된 부호·열·상태·분류·귀속 정책을 `personal/finance-layout.md`에 대응시켜 적용합니다. 표현이 다르다는 이유로 원본을 바꾸지 않습니다.

식별자나 상태 저장 위치가 없으면 필요한 보조 열·보조 표를 제안하거나 해당 기능을 제한합니다. 존재하지 않는 ID를 있다고 가정하지 않습니다. 기존 집계가 출금일 기준이면 이용일 소비와 구분해 명명하고, 두 지표를 같은 것으로 표현하지 않습니다.


## 필수 사실과 상태

- 거래 ID는 전역 유일하며 한 번 부여하면 유지합니다. 행 번호는 ID가 아닙니다.
- 일자·금액·통화·실제 수단·부담자·용도·거래 관계를 확인합니다. 해당하지 않는 필드는 적용하지 않으며 필수 사실이 불명확하면 `확인필요`입니다.
- 상태는 `확정`, `확인필요`, `예정`, `중복제외`입니다. 예상·미확인·참조행은 확정 집계에서 제외합니다.
- 금액은 양수로 저장하고 방향은 출금/입금 계좌와 유형으로 표현합니다. 0원·음수로 차액을 메우지 않습니다. 미확인 금액은 빈칸입니다.
- 날짜는 실제 이용일/이체일을 사용합니다. 승인·청구·결제·환급일이 다르면 비고에 역할별로 보존합니다.
- 가계부의 순소비는 이용일 기준입니다. 현금이 출금된 날의 합계와 같은 지표가 아닙니다.

## 유형과 집계

| 유형 | 수입 | 순소비 | 예 |
|---|---|---|---|
| 소득 | 금액 | 0 | 급여·사업·이자 등 확인된 유입. 하위분류로 구분 |
| 소비 | 0 | 금액 | 본인이 실제 부담하는 구매 |
| 소비환급 | 0 | -금액 | 확인된 구매의 취소·일부 환불·타인 부담 회수 |
| 이체 | 0 | 0 | 내 통장 간 이동·저축·투자·연금 원금 납입/회수 |
| 카드대금 | 0 | 0 | 이미 기록한 카드 구매대금의 결제 |
| 대납 | 0 | 0 | 타인이 전부 부담할 돈을 내가 대신 지급 |
| 대납회수 | 0 | 0 | 대납 원금의 회수 |
| 기타유입 | 0 | 0 | 성격 미확정 유입. 확정 전 확인필요로 유지 |
| 기타유출 | 0 | 0 | 성격 미확정 유출. 확정 전 확인필요로 유지 |
| 포인트 | 0 | 0 | 비현금 보조 기록 |

지원금·증여 등은 성격을 확인한 뒤 `소득/INC-SUPPORT`로 분리합니다. 이 템플릿의 ‘수입’은 근로소득만을 뜻하지 않습니다. 대출 실행·상환 원금은 본인 대출 계좌와의 `이체`, 확인된 이자·수수료는 `소비`로 구분합니다.

`기타유입/기타유출`은 임시 보관 유형입니다. 확인된 기타 수입·소비는 각각 `소득/INC-OTHER`, `소비/EXP-OTHER`로 기록합니다. 임시 유형을 확정으로 두고 집계에서 누락시키지 않습니다.

## 중복 방지

1. 원천 종류·계좌 별칭·원천 키를 함께 비교합니다. 실제 계좌번호를 키에 쓰지 않습니다.
2. 같은 원천 키와 내용이면 무변경입니다. 같은 키인데 금액·날짜가 다르면 기존 ID의 정정 후보입니다.
3. 원천 키가 없으면 일시·수단·내용·금액·승인번호 등을 대조합니다. 같은 날 같은 금액만으로 동일 거래라고 판단하지 않습니다.
4. 은행 출금·카드 승인·간편결제 주문이 같은 구매를 가리키면 소비 대표행은 한 건입니다. 나머지는 연결 ID를 가진 `중복제외` 참조행으로 보존할 수 있습니다.
5. 내부이체는 출금·입금 계좌를 가진 대표행 하나로 기록합니다. 양쪽 명세서가 들어와도 자금이동을 두 번 생성하지 않습니다.
6. 한 원천 거래를 여러 구성으로 나누면 원천 키와 구성 키를 각각 보존합니다. 별개의 동일 금액 구매를 분할 구성으로 합치지 않습니다.
7. 같은 자료를 두 번 적용할 때 두 번째 신규 거래가 0건인지 확인합니다.

## 환불·대납·할부

- 소비환급은 연결거래ID에 원구매 ID를 적고 원구매 분류를 사용합니다. 동일 환불의 참조 자료를 중복 차감하지 않습니다.
- 기본 방식은 원구매 총액 유지 + 별도 환급행입니다. 원구매를 이미 순액 정정했다면 같은 환불행을 다시 만들지 않습니다.
- 환급 누계가 원구매 부담액을 넘으면 자동 반영하지 않고 사유를 확인합니다. 환불 예정은 확정 환급이 아닙니다.
- 다른 달 환불은 실제 환불일에 기록하고 원구매 ID와 이용월을 보존합니다. 기본 월별 순소비는 환불 발생월에 차감합니다. 과거 월 재작성은 사용자 정책 확인 후 수행합니다.
- 처음부터 타인 전액 부담인 거래는 대납/대납회수입니다. 공동 구매는 본인 부담과 타인 부담을 확인해 분리하고 분할 합계를 보존합니다.
- 할부 구매는 이용일에 총원금을 한 번 기록합니다. 월 납부는 카드대금이며 이자만 소비로 분리합니다. 시작 전 할부는 기초 채무로 확인하고 당월 소비를 가상 생성하지 않습니다.
- 포인트 혼합결제는 실제 현금/카드 부담만 소비에 포함합니다. 포인트 사용은 별도 보조 기록으로 연결합니다.

## 변경과 검증

- 쓰기 전 실제 대상 행·ID·수식·데이터 검증을 확인합니다. 과거 자료를 읽지 못하면 신규라고 가정하지 않습니다.
- 삭제 대신 정정 또는 중복제외를 우선합니다. 정정은 ID를 유지하고 `변경이력`에 시각·대상·필드·이전/이후·사유를 기록합니다.
- 반영 뒤 건수·유형별 금액·수식 결과를 재조회합니다. 같은 자료를 반복해 정정 이력을 늘리지 않습니다.
- 잔액 검증에는 확인된 기초·입출금·기말과 해당 자료 범위가 필요합니다. 차액은 미결로 두고 맞추기용 거래를 만들지 않습니다.
- 기준통화가 아닌 거래는 별도 확인 대상으로 표시합니다. 통화가 다른 금액을 그대로 더하지 않습니다.
- `확인필요 0건`은 자료 수집 완료를 뜻하지 않습니다. `자료범위`의 기대 기관·수단·기간과 대조합니다.

## 분류 변경

분류 ID는 고정하고 이름은 수정할 수 있습니다. 사용 중지한 분류도 과거 조회를 위해 남겨둡니다. 기본 분류를 새로 가져와 운영 시트에 일괄 적용하지 않습니다. 기존 분류의 유지·계층 확장은 개인 운영지침에서 정합니다. 상세 절차는 [개인화 안내](../../docs/customizing.md)를 따릅니다.

## 원천 데이터의 안전한 저장

[안전 입력 지침](../../docs/safe-input.md)을 따릅니다. 원천 텍스트를 수식으로 해석하지 않으며 자동 입력은 RAW/명시적 문자열을 사용합니다. 수동 입력·외부 CSV·정정 이력도 같은 기준으로 확인합니다. 도구의 안전한 쓰기·수식 여부를 확인할 수 없으면 적용을 보류합니다.
