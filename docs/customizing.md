# 계좌와 계층 분류 바꾸기

아래는 신규 추천 양식의 개인화 방법입니다. 기존 시트는 현재 계좌·분류 표현을 유지하고 개인 운영지침에 따라 변경합니다. 부모ID·Depth 열을 반드시 추가할 필요는 없습니다. 계층 확장이 필요할 때 보완안을 선택합니다.

## 계좌 후보 6개

| ID | 별칭 | 유형 | 보고분류 |
|---|---|---|---|
| CASH-001 | 지갑현금 | 현금 | 현금 |
| BANK-001 | 주거래통장 | 입출금 통장 | 현금 |
| SAVE-001 | 저축계좌 | 저축 | 저축 |
| INVEST-001 | 투자계좌 | 투자 | 투자 |
| PENSION-001 | 연금계좌 | 연금 | 연금 |
| LOAN-001 | 대출계좌 | 대출 | 부채 |

기본은 모두 후보·보유 미확인입니다. 실제 쓰는 계좌만 사용으로 전환하며 잔액은 근거와 기준일이 있을 때만 적습니다. 같은 유형을 여러 개 쓰면 BANK-002처럼 새 ID를 추가합니다. 이름은 바꿀 수 있고 ID는 유지합니다. 카드는 별도 계좌 유형을 만들지 않고 원장의 결제수단 별칭으로 기록합니다.

## 기본 분류 트리

```text
수입 (Depth 1)
  근로소득 (Depth 2)
  투자소득 (Depth 2)
  부수입 (Depth 2)
소비 (Depth 1)
  식비 (Depth 2)
  주거비 (Depth 2)
  통신·관리비 (Depth 2)
  쇼핑 (Depth 2)
  교통비 (Depth 2)
  병원비 (Depth 2)
```

자금이동·대납·미확인·포인트는 소비와 섞이지 않도록 별도 최상위 분류로 제공합니다. 투자소득에는 확인된 이자·배당·실현수익을 구분해 넣을 수 있지만 투자 원금 회수 전체를 수입으로 넣지 않습니다. 확인되지 않은 수익을 계산해 생성하지 않습니다.

## Depth 확장 예

`소비 > 식비 > 외식`, `소비 > 식비 > 장보기`를 추가하려면 `설정!A:K`에 새 ID를 만들고 부모ID를 EXP-FOOD로 지정합니다. Depth는 3입니다. 기존 분류를 고정된 대분류/소분류 두 칸으로만 제한하지 않습니다.

AI에게 다음과 같이 요청하세요.

```text
내 가계부 설정을 읽고 식비 아래 외식과 장보기를 추가해줘.
부모ID는 EXP-FOOD로 연결하고 고유 ID와 Depth 3을 부여해줘.
전체경로·대분류·선택분류를 다시 계산하고 드롭다운을 갱신해줘.
기존 식비 거래의 ID와 금액은 유지해줘.
부모 직접 거래와 후손을 한 번씩만 합산하는지 확인해줘.
```

## 변경 규칙

- 분류ID는 고정합니다. 이름·순서는 변경할 수 있습니다.
- 이름이나 부모를 바꾸면 해당 노드와 모든 후손의 Depth·전체경로·대분류·선택분류를 갱신합니다.
- 부모는 존재해야 하며 자기 자신·후손을 부모로 지정할 수 없습니다.
- 하위 노드는 상위의 구분·허용유형 범위를 따릅니다. 소비 아래 소득을 넣지 않습니다.
- 신규 거래는 사용 중인 최하위 노드만 선택합니다. 부모가 중지되면 후손도 신규 후보에서 제외합니다.
- 사용 중지한 분류도 과거 조회를 위해 남깁니다. 과거 거래 재분류는 별도 확인·변경이력을 남깁니다.
- 기본 분류 CSV를 다시 가져와 개인 설정을 덮어쓰지 않습니다.

필드와 시트 배치는 [시트 구성](sheets-setup.md)을 따릅니다.
