# 기존 가계부를 유지하며 시작하기

이미 사용하는 Google Sheets가 있으면 이 경로를 선택합니다. 기존 탭·열·수식·계좌·분류를 기본 양식으로 교체하지 않습니다. 기존의 평면 분류나 월별 탭도 유지할 수 있습니다.

## 1. 원본을 읽기 전용으로 진단

AI에게 개인 저장소와 기존 가계부 URL을 주고 다음을 요청합니다.

```text
기존 시트를 유지하며 lifos를 적용하고 싶어.
docs/existing-sheet.md에 따라 먼저 읽기 전용으로 진단해줘.
현재 탭·헤더·입력 방식·계산 영역·분류·집계 기준을 확인해줘.
지원 가능한 기능과 부족한 부분을 설명하고 개인 운영지침 초안을 만들어줘.
아직 원본 셀·수식·분류를 변경하거나 기본 탭을 생성하지 마.
```

AI는 메타데이터·실제 헤더부터 읽고 필요한 범위의 표본을 확인합니다. 전체 금융 내역을 불필요하게 가져오거나 GitHub에 복제하지 않습니다. 월별 탭·숨김 탭·이름 지정 범위·연결 수식도 작업 영향 범위에서 확인합니다.

| 진단 항목 | 확인할 내용 |
|---|---|
| 데이터 구조 | 단일 원장/월별 탭/수입·지출 별도 표/요약표만 존재 |
| 날짜 | 실제 날짜/문자열, 이용일/출금일/청구월의 의미 |
| 금액 | 수입·지출 열 분리/부호 구분, 환불·이체 표현, 통화 |
| 계좌·수단 | 실제 저장 위치, 별칭·ID, 카드와 통장의 관계 |
| 분류 | 목록 위치, 단계 수, 계층 표현, 신규 분류 추가 방법 |
| 입력 경계 | 입력 가능 범위, 수식·배열 출력·조회 전용 영역 |
| 식별·중복 | 거래 ID·원천 키·승인번호 등 안정적인 근거 |
| 확인·누락 | 미확인·예정·중복 제외 상태와 자료 수집 범위 저장 위치 |
| 집계 | 수입·소비·이체·환불 처리, 귀속월, 현재 합계 수식 의미 |
| 수정·재개 | 정정 이력, 구조 변경 감지,새 월 처리 |

읽지 못한 범위나 뜻이 불명확한 열은 미확인으로 표시하고 사용자에게 묻습니다. 거래 행이 없는 요약표에서 개별 거래를 복원하지 않습니다.

## 2. 가능한 기능과 최소 보완안 제시

진단 결과를 아래 세 가지로 구분합니다.

- **현재 지원:** 확인한 구조 그대로 수행 가능한 작업.
- **보완 후 지원:** 필요한 열·보조 표·정책 확인과 영향 범위를 명시한 작업.
- **현재 미지원:** 근거·구조가 부족하여 수행하거나 검증할 수 없는 작업.

예: 거래 식별 근거가 없으면 중복 자동 처리 완료를 보장하지 않습니다. 보조 ID 열 추가를 제안하거나 조회·요약만 지원합니다. 월간 합계만 있으면 요약 점검은 가능하지만 개별 거래 추가·환불 연결은 지원하지 않습니다.

확인 상태나 정정 이력 위치가 필요하면 기존 메모 열 활용 또는 작은 보조 표를 제안합니다. 사용자가 선택하기 전에는 원본에 만들지 않습니다. 운영 상태·목록은 Sheets에 두며, 저장 위치가 없으면 해당 기능을 보류합니다.

신규 양식의 양수 금액·상태명·계층 분류를 강제하지 않습니다. 출금일 소비와 이용일 소비, 카드 청구액과 구매 소비처럼 의미가 다른 지표는 명확히 구분합니다. 중복·누락 위험이 있으면 기존 합계가 올바르다고 무조건 인정하지 않고 차이와 개선안을 제시합니다.

## 3. 개인 운영지침 초안 검토

[운영지침 양식](../personal/finance-layout.example.md)을 개인 Private 저장소의 `personal/finance-layout.md`로 작성합니다. 실제 시트 위치·처리 방식·지원 범위만 기록하고 거래·잔액·개인 분류 목록은 복사하지 않습니다.

사용자는 현재 구조 설명이 맞는지, 어떤 기능을 사용할지, 제안한 보완 중 무엇을 반영할지 선택합니다. 변경을 원하지 않으면 원본을 유지하고 지원 가능한 범위만 확정합니다.

## 4. 원본과 분리한 복사본에서 검증

1. 기존 스프레드시트 전체의 개인 비공개 복사본을 준비하고 원본과 다른 파일인지 확인합니다. 외부 참조가 원본을 가리키는지도 확인합니다.
2. 기록·합계·핵심 수식의 변경 전 상태를 확인합니다. 필요한 범위만 비교하고 실제 값을 공개 저장소에 남기지 않습니다.
3. 현재 열·부호·분류·날짜 방식에 맞춘 가상 거래를 복사본의 허용 입력 위치에 넣습니다. 기본 CSV를 통째로 붙이지 않습니다.
4. 지원하기로 한 기능에 대해 신규 입력, 같은 자료 재입력, 이체·카드대금 제외, 환불, 미확인 처리, 합계 증감, 기존 수식 보존을 확인합니다.
5. 지원하지 않는 기능은 시험 통과로 표시하지 않습니다. 잘못된 날짜·동일 금액 별개 거래·새 월 탭 등 해당 구조의 예외도 확인합니다.
6. 통과/실패/미실행과 남은 제약을 보고합니다. 복사본의 가상 거래를 원본으로 옮기지 않습니다.

## 5. 선택한 변경만 적용하고 재개 확인

이미 선택한 범위 안에서만 적용합니다. 실행 직전 실제 원본 구조와 값이 변하지 않았는지 확인하고 반영 후 재조회합니다. 변경이 필요 없으면 개인 운영지침만 확정합니다.

새 대화에서 운영지침과 실제 시트를 읽어 같은 위치·지원 범위를 복원할 수 있는지 확인합니다. 매 작업마다 탭·헤더·수식 경계를 대조하며 불일치가 생기면 영향받는 쓰기를 멈추고 차이를 설명합니다. 표준 7개 탭으로 초기화하지 않습니다.

완료 조건: 사용자가 선택한 범위가 검증되어 있고, 현재 지원 기능·미지원 기능·미확인 항목·실제 저장 여부가 구분됩니다. 진단만 끝났다면 운영 준비완료가 아닙니다.

## 원천 데이터의 안전한 저장

[안전 입력 지침](safe-input.md)을 따릅니다. 원천 텍스트를 수식으로 해석하지 않으며 자동 입력은 RAW/명시적 문자열을 사용합니다. 수동 입력·외부 CSV·정정 이력도 같은 기준으로 확인합니다. 도구의 안전한 쓰기·수식 여부를 확인할 수 없으면 적용을 보류합니다.
