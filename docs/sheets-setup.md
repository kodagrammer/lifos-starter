# 신규 Google Sheets 추천 구성

이 문서는 **신규 경로를 선택한 경우에만** 사용하는 추천 구성입니다. 기존 가계부는 [기존 시트 진단](existing-sheet.md)을 먼저 따르고, 아래 탭·열·수식을 적용하지 않습니다.

AI가 빈 가계부를 구성하거나 사용자가 수동 적용할 때의 기준입니다. 기존 개인 시트를 바꾸기 전에는 실제 구조부터 읽습니다. 표준 이름을 이유로 기존 탭을 삭제하거나 교체하지 않습니다.

## 1. 탭과 초기 파일

새 가계부에는 다음 7개 탭을 만듭니다. CSV는 값과 헤더만 담으며 수식·드롭다운·보호 설정은 별도로 적용합니다.

| 탭 이름 | 초기 파일 | 역할 |
|---|---|---|
| 계좌관리 | [accounts.csv](../system/finance/templates/accounts.csv) | 계좌 후보·실제 사용 계좌·잔액·확인일 |
| 설정 | [categories.csv](../system/finance/templates/categories.csv), [preferences.csv](../system/finance/templates/preferences.csv) | A:K 계층 분류표, N:P 개인 운영 설정 |
| 거래원장 | [ledger.csv](../system/finance/templates/ledger.csv) | A:P 입력, Q:U 계산, V 확인 메모, W 결제수단 |
| 가계부 | 아래 조회 구성 | 월 선택·수입·순소비·거래 조회 |
| 자료범위 | [coverage.csv](../system/finance/templates/coverage.csv) | 기간별 수집 예정·실제 범위 |
| 변경이력 | [changes.csv](../system/finance/templates/changes.csv) | 거래·분류·계좌 정정 기록 |
| 월간점검 | [monthly-review.csv](../system/finance/templates/monthly-review.csv) | 월별 점검 결과와 미결 |

AI가 쓸 수 있으면 직접 만들고 재조회합니다. 수동이면 GitHub에서 CSV를 열어 Raw/Download raw file로 저장한 뒤 Sheets의 **파일 → 가져오기 → 업로드 → 새 시트 삽입**으로 추가하고 이름을 바꿉니다. 구분자는 쉼표 또는 자동 감지를 선택합니다. 기존 스프레드시트 전체 교체는 선택하지 않습니다. [Google 파일 가져오기 안내](https://support.google.com/docs/answer/12236443?hl=ko)

`preferences.csv`는 별도 임시 탭으로 가져온 후 A:C를 `설정!N1:P`로 복사합니다. 값이 맞는지 확인한 뒤 임시 탭만 제거합니다. 분류표 A:K를 덮어쓰지 않습니다. 빈 원장 CSV에는 헤더 한 줄만 있습니다.

## 2. 계좌관리 A:K

헤더: `계좌ID, 별칭, 유형, 보고분류, 통화, 소유, 사용, 확인잔액, 기준일, 근거, 비고`.

계좌 유형은 **현금 / 입출금 통장 / 저축 / 투자 / 연금 / 대출** 6개입니다. 보고분류는 현금/저축/투자/연금/부채이며 대출은 부채입니다. 소유는 본인/타인/미확인, 사용은 사용/후보/중지입니다.

기본 후보는 각 유형 하나씩이며 잔액·기준일은 빈칸입니다. 같은 유형을 여러 개 쓰면 새 계좌 ID를 추가합니다. 후보를 실제 보유 계좌로 간주하지 않습니다. 대출 잔액은 확인된 미상환 원금의 양수이며 현금 잔액과 단순 합산하지 않습니다.

카드는 계좌 유형에 넣지 않습니다. 원장의 W 결제수단에 카드 별칭을 적고, 카드대금 출금 계좌는 E에 실제 통장 ID를 적습니다. 카드 구매·환불의 E/F를 결제 통장으로 채워 즉시 현금 이동이 있었다고 표현하지 않습니다. 카드 청구·부채 자동 관리는 이번 골격에 포함하지 않습니다. 거래 집계와 전체 자산·부채 대사는 구분합니다.

## 3. 설정: 계층 분류와 운영 설정

분류표 A:K:

| 열 | 필드 | 기준 |
|---|---|---|
| A | 분류ID | 고유·불변 |
| B | 부모ID | 상위 분류 ID. 최상위는 빈칸 |
| C | Depth | 최상위 1, 부모 Depth+1 |
| D | 분류명 | 화면 표시 이름 |
| E | 구분 | 소득/소비/자금이동/대납/기타/포인트 |
| F | 사용 | 사용/중지 |
| G | 정렬 | 같은 부모 안에서 표시할 순서 |
| H | 허용유형 | 세로줄 구분. 예: 소비|소비환급 |
| I | 전체경로 | 부모 경로 + ` > ` + 분류명 |
| J | 대분류 | Depth 2 조상 이름. Depth 1은 빈칸 |
| K | 선택분류 | 해당 노드의 분류명 |

A/B/D/E/F/G/H는 입력 기준이고 C/I/J/K는 계층에서 계산한 파생값입니다. CSV에는 초기 파생값이 들어 있습니다. AI가 분류를 추가·이동·이름 변경할 때 영향받는 모든 후손의 파생값을 다시 계산하고 재조회합니다. 수동으로 바꿀 때도 이 작업을 요청합니다. CSV 자체가 자동 계산 기능을 제공하지는 않습니다.

분류 선택은 **사용 중인 최하위 노드만** 허용합니다. 기본은 Depth 2까지이며 `소비 > 식비 > 외식`처럼 Depth 3 이상을 추가할 수 있습니다. 부모 분류와 하위 거래를 동시에 합산하지 않습니다. 분류별 합계는 선택한 노드와 모든 후손 거래를 포함하며 거래 ID당 한 번만 셉니다.

부모 ID 존재·순환 없음·Depth 일치·구분/허용유형 상속·경로 일치를 확인합니다. 자식이 있는 노드는 신규 거래 선택에서 제외합니다. 과거 거래가 있는 노드에 자식을 추가하면 과거 거래의 기존 ID는 유지하고 부모 직접 거래와 후손을 함께 집계합니다. 과거 거래의 이동은 별도 확인합니다.

운영 설정 N:P: `설정키, 값, 설명`. 분류표와 분리합니다.

| 셀 | 설정키 | 기본값 |
|---|---|---|
| O2 | 기준통화 | KRW |
| O3 | 시간대 | Asia/Seoul |
| O4 | 시작월 | 사용자 확인 후 월 초 날짜 |
| O5 | 소비귀속 | 이용일 |
| O6 | 환불귀속 | 환불발생월 |
| O7 | 템플릿버전 | 0.3.2 |

기준통화 한 종만 집계하며 환율을 자동 추정하지 않습니다. 운영 설정을 바꾸면 과거 데이터 영향도 확인합니다.

## 4. 거래원장 A:W

| 열 | 헤더 | 입력·계산 |
|---|---|---|
| A | 거래ID | 유일한 ID, 예: TX-000001 |
| B | 일자 | 실제 날짜 값, yyyy-mm-dd 표시 |
| C | 유형 | 공통 규칙의 10개 유형 |
| D | 상태 | 확정/확인필요/예정/중복제외 |
| E | 출금계좌ID | 내부 소유 계좌 ID. 외부 지급자는 빈칸 |
| F | 입금계좌ID | 내부 소유 계좌 ID. 외부 가맹점은 빈칸 |
| G | 금액 | 양수 숫자. 미확인은 빈칸 |
| H | 통화 | 계좌 통화와 대조 |
| I | 분류ID | 설정의 분류 ID. 이름 직접 입력 금지 |
| J | 내용 | 확인한 사용 목적·원문 구분 |
| K | 원천 | 수동/카드명세/은행명세 등 |
| L | 원천거래키 | 원천 내 안정적인 키. 없으면 빈칸 |
| M | 구성키 | 한 원천을 분할한 경우 구성 식별 |
| N | 연결거래ID | 환불·대납 회수·참조행의 원거래 |
| O | 비고 | 부담자·정정·미확인 근거 |
| P | 입력방법 | 대화/파일/수동 등 실제 경로 |
| Q | 귀속월 | 계산. 월 초 날짜 |
| R | 대분류 | 계산. 분류표 조회 |
| S | 선택분류 | 계산. 선택 노드명 조회 |
| T | 집계수입 | 계산. 확정·기준통화 소득 |
| U | 집계순소비 | 계산. 확정·기준통화 소비-환급 |
| V | 확인메모 | 미확인 필드·검증 실패 이유 등 |
| W | 결제수단 | 현금·계좌·카드 별칭 등. 카드 별칭은 계좌 ID가 아님 |

출금/입금 계좌는 내부 자금이동의 계좌를 지정합니다. 카드 구매·카드 환불은 E/F를 비워두고 W에 같은 카드 별칭을 적습니다. 카드대금은 E=결제 통장, F=빈칸, W=카드 별칭으로 기록합니다. 카드대금은 소비로 집계하지 않습니다. 현금·통장으로 직접 결제한 구매는 E에 실제 출금 계좌를 적습니다.

## 5. 초기 계산 수식

다음은 **새 빈 탭 전용** 초기 수식입니다. 운영 시트에서는 기존 수식과 실제 헤더를 먼저 확인합니다. 앵커 아래가 비어 있어야 하며 Q:U 배열 출력에는 값을 직접 넣지 않습니다. 오류를 숨기려고 계산 영역을 0으로 바꾸지 않습니다.

`거래원장!Q2` (표시 형식 yyyy-mm):

```text
=ARRAYFORMULA(IF(A2:A="","",IF(ISNUMBER(B2:B),DATE(YEAR(B2:B),MONTH(B2:B),1),"날짜확인")))
```

`거래원장!R2`:

```text
=ARRAYFORMULA(IF(A2:A="","",IFNA(VLOOKUP(I2:I,'설정'!A2:K,10,FALSE),"미등록")))
```

`거래원장!S2`:

```text
=ARRAYFORMULA(IF(A2:A="","",IFNA(VLOOKUP(I2:I,'설정'!A2:K,11,FALSE),"미등록")))
```

`거래원장!T2`:

```text
=ARRAYFORMULA(IF(A2:A="","",IF((D2:D="확정")*(H2:H='설정'!O2)*(C2:C="소득"),G2:G,0)))
```

`거래원장!U2`:

```text
=ARRAYFORMULA(IF(A2:A="","",IF((D2:D="확정")*(H2:H='설정'!O2),IF(C2:C="소비",G2:G,IF(C2:C="소비환급",-G2:G,0)),0)))
```

수식은 의미 검증을 대신하지 않습니다. 확정 전 필수값·계좌·유형/분류 조합을 검증합니다. 미등록 분류나 잘못된 상태가 있으면 결과를 정상 점검으로 발행하지 않습니다.

## 6. 가계부 조회 화면

`가계부!A1`에 `선택월`, `B1`에 조회할 달의 월 초 날짜를 넣고 yyyy-mm으로 표시합니다. `D1`에 `상태`, `E1`에는 처음 `자료 미확인`을 넣습니다. 월간점검에서 자료 완비를 확인한 뒤 상태를 바꿉니다.

| 셀 | 항목 | 값·수식 |
|---|---|---|
| A3 | 수입 | 항목명 |
| B3 | 선택월 수입 | `=SUMIFS('거래원장'!T2:T,'거래원장'!Q2:Q,$B$1)` |
| A4 | 순소비 | 항목명 |
| B4 | 선택월 순소비 | `=SUMIFS('거래원장'!U2:U,'거래원장'!Q2:Q,$B$1)` |
| A5 | 확인필요 건수 | 항목명 |
| B5 | 해당 월 미확인 | `=COUNTIFS('거래원장'!Q2:Q,$B$1,'거래원장'!D2:D,"확인필요")` |
| A6 | 기준통화 외 건수 | 항목명 |
| B6 | 해당 월 외화 | `=COUNTIFS('거래원장'!Q2:Q,$B$1,'거래원장'!H2:H,"<>"&'설정'!O2,'거래원장'!H2:H,"<>")` |

A8:W8에 원장 헤더를 복사하고 `가계부!A9`에 입력합니다.

```text
=IFNA(FILTER('거래원장'!A2:W,'거래원장'!Q2:Q=$B$1),"해당 월 기록 없음")
```

가계부 A9:W는 조회 출력이며 거래를 직접 입력하지 않습니다. 날짜가 잘못되어 선택월에 나타나지 않는 거래, 통화가 빈 거래, 원장 전체의 미등록 분류도 별도로 확인합니다. 빈 가계부의 0원은 ‘현재 입력된 확정 거래 합계’이며 실제 수입·지출이 없었다는 증명이 아닙니다.

## 7. 입력 편의와 보호

1. 스프레드시트 지역은 대한민국으로 설정하고 날짜·통화 표시를 확인합니다. 시간대는 개인 설정에 맞춥니다.
2. 모든 표의 첫 행을 고정합니다. 거래원장에는 필터를 적용합니다.
3. 거래원장 C/D, 계좌관리 C/D/F/G, 설정 F에 허용값 드롭다운을 설정합니다.
4. E/F 계좌 ID와 I 분류 ID는 현재 사용 중인 목록을 후보로 제공합니다. 중지된 과거 ID를 지우거나 기존 거래를 무효화하지 않습니다.
5. 거래원장 Q:U, 가계부 수식·조회 영역을 보호하고 입력 영역과 다른 색으로 표시합니다.
6. G 금액은 양수 숫자, B 일자는 유효 날짜인지 확인합니다. 원천 CSV의 날짜·금액이 텍스트로 남지 않았는지 검사합니다.
7. 가상 5건으로 수식·드롭다운·반복 입력을 검증하고 결과를 재조회합니다. 이 배포물만으로 라이브 수식 검증을 마쳤다고 말하지 않습니다.

## 8. 자료범위·월간점검

`자료범위`는 계좌·수단별 기대 기간, 받은 기간, 수집 상태와 누락을 관리합니다. 실제 사용하는 계좌·카드마다 해당 월 범위가 있어야 합니다. 자료가 없는 것을 거래가 없는 것으로 바꾸지 않습니다.

자료범위 상태는 `미수집/일부수집/수집완료/해당없음`을 사용합니다. `해당없음`은 사용자나 증빙으로 확인된 경우에만 근거와 함께 사용합니다. 대상월은 월 초 날짜이며 기대·수집 시작/종료일은 실제 날짜입니다. `수집완료`는 입력·대사·월간 점검 완료와 다릅니다.

`월간점검`에는 수입·순소비·미확인 건수·수집 상태·사용자 확인·결과를 기록합니다. 수집이 덜 끝난 점검은 `부분점검`입니다. 월 종료·기간 전체 자료·중복/환불/분류 검증·사용자 사실 확인이 끝나면 `점검완료`로 표시합니다. 이는 전체 자산·부채를 확정하는 재무 마감과 다릅니다.

점검의 사용자확인은 `미확인/확인완료`로 기록하고 확인일시·근거를 남깁니다. 변경이력의 변경시각과 점검시각에는 시간대를 포함합니다. 처리자는 사람 이름 대신 `사용자/AI` 같은 역할 별칭으로 남겨도 됩니다.

공식 수식 문서: [ARRAYFORMULA](https://support.google.com/docs/answer/3093275?hl=ko), [VLOOKUP](https://support.google.com/docs/answer/3093318?hl=ko), [FILTER](https://support.google.com/docs/answer/3093197?hl=ko).

## 원천 데이터의 안전한 저장

[안전 입력 지침](safe-input.md)을 따릅니다. 원천 텍스트를 수식으로 해석하지 않으며 자동 입력은 RAW/명시적 문자열을 사용합니다. 수동 입력·외부 CSV·정정 이력도 같은 기준으로 확인합니다. 도구의 안전한 쓰기·수식 여부를 확인할 수 없으면 적용을 보류합니다.
