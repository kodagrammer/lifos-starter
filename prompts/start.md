# 처음 시작할 때

AI는 README의 개인 URL과 함께 이 절차를 따른다. 사용자에게 한 번에 하나씩 다음 행동을 안내한다.

## 공통 시작

1. 개인 GitHub 소유자·Private 여부를 확인한다. 확인 도구가 없으면 사용자에게 화면 확인을 요청한다. 확인 전 개인 자료를 쓰지 않는다.
2. AGENTS.md, 개인 profile/progress/finance-layout가 있으면 읽고 현재 단계부터 재개한다.
3. GitHub 읽기/원격 저장, Sheets 읽기/쓰기를 각각 확인한다. 불가능한 기능은 수동 적용으로 전환하고 적용 여부를 구분한다.
4. **“기존에 쓰던 Google Sheets 가계부가 있나요?”**를 묻는다. 사용 중인 자료가 있으면 기존 경로다. 빈 시트만 만들어둔 경우에는 신규 경로를 선택할 수 있다. 이미 답한 것은 다시 묻지 않는다.

## A. 신규 경로

1. docs/sheets-setup.md의 추천 양식을 설명하고 기본 계좌 6종·분류 선택을 확인한다.
2. 별도 `lifos 연습용 — 가상 자료` 시트에 BANK-001/SAVE-001과 가상카드 별칭을 준비한다. 기준통화 KRW, 시작월 2000-01-01로 한다.
3. examples/finance/ledger.csv의 5건을 적용해 수입 1,000,000원·순소비 80,000원과 같은 자료 재입력 시 신규 0건을 확인한다. 라이브 실행 전에는 검증 완료라고 말하지 않는다.
4. 시작월·통화·시간대·실제 사용할 계좌·결제수단·분류를 확인하고 운영 시트의 추천 7개 탭·수식·드롭다운을 구성한다. 운영 원장에 가상 거래를 넣지 않는다.
5. 실제 생성한 구조에 맞게 personal/finance-layout.md를 작성한다. 추천 구성에서 달라진 사항도 반영한다.

## B. 기존 시트 경로

1. docs/existing-sheet.md에 따라 원본을 읽기 전용으로 진단한다. 추천 탭이나 기본 분류를 먼저 생성하지 않는다.
2. 실제 구조·입력 방식·집계 의미·분류·보호 영역을 확인하고 가능한 기능과 제약을 설명한다.
3. personal/finance-layout.example.md를 바탕으로 운영지침 초안을 만든다. 미확인 위치·의미는 추측하지 않는다.
4. 구조 유지 또는 최소 보완안을 제시하고 사용자가 적용할 범위를 선택하게 한다. 별도 정책·분류 변경을 원하지 않으면 현재 방식을 유지한다.
5. 원본과 분리한 복사본에서 실제 시트 방식에 맞는 입력·반복 입력·집계·수식 보존을 검증한다. 표준 CSV를 그대로 덮어쓰지 않는다.
6. 검증이 끝나면 선택한 변경만 원본에 반영하고 재조회한다. 원본 변경이 없으면 운영지침만 확정한다. 지원 불가 기능은 미지원으로 기록한다.

## 공통 마무리

1. 개인 Private GitHub에 profile.md, progress.md, finance-layout.md를 저장한다. 계좌·분류 목록·거래·잔액은 중복 저장하지 않는다.
2. 원격 파일과 운영 시트 설정을 재조회한다. 로컬 변경과 원격 저장을 구분한다.
3. `선택 경로 / 지원 기능·제약 / 검증한 범위 / 저장 위치·여부 / 미확인 / 다음 행동`을 알린다.
4. 첫 실제 기록과 새 대화에서 재조회는 설정 완료와 별도로 검증한다. prompts/record.md와 resume.md로 연결한다.

원천 데이터 쓰기 전 `docs/safe-input.md`를 읽는다. 원천 텍스트·날짜·숫자·신뢰한 계산 수식을 분리하고 선택한 쓰기 경로의 안전성 및 사후 실제 저장값·수식 여부를 확인한다. 확인할 수 없으면 해당 쓰기를 보류한다.
